# The golden probe corpus (S130-A MPRB-04)

Real `ffprobe` documents from the operator's 16,221-title library, scrubbed of
everything identifying, with their expected parse results.

Produced by `ffprobe 5.1.9-0+deb12u1` on <host> — the deployment host — against
files under its live library mount. Every value in a `*.json` here is what that
binary actually emitted, except the values the scrubber deliberately replaced.

## Layout

| file | what it is |
|---|---|
| `<name>.json` | a scrubbed `ffprobe -show_format -show_streams -show_chapters` document |
| `<name>.failure.json` | a run that exited non-zero: `{exit_code, success, stderr, stdout}` |
| `<name>.expected` | the golden parse result, rendered by `media::probe_golden::render` |
| `_raw/` | **git-ignored** drop box for unscrubbed captures. Never commit anything from here. |

## The rule about `_raw/`

A raw capture contains absolute paths, episode and film titles, release-group
names and external database ids. It is git-ignored and it stays that way. The
only thing that ever gets committed is the output of
`media::probe_capture::scrub_probe_document`, which is an **allowlist** — a
string whose JSON path is not explicitly kept or synthesized is replaced with
`<redacted>` — followed by an independent shape-based re-scan that returns an
error rather than a document if anything identifying survived.

`media::probe_golden::tests::no_committed_corpus_file_contains_residual_pii`
runs that scan over every file in this directory on every `cargo test`.

## Adding a fixture

1. Capture on a host that has both `ffprobe` and the library, writing
   `<name>.stdout.json`, `<name>.stderr.txt` and `<name>.rc.txt` into `_raw/`.
2. `cargo test --bin muse -- --ignored mint_fixtures`
3. Add the name to `OK_FIXTURES` or `FAILURE_FIXTURES` in
   `src/media/probe_golden.rs`, **and** write a hand-written
   `the_hand_written_facts_about_<name>` assertion. A test refuses a fixture
   that has only a self-generated `.expected` — a golden regenerated by the
   parser it guards proves stability, not correctness.
4. Do not hand-edit a `.json` or a `.expected`. Re-mint instead.
